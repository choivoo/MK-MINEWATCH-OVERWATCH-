# 로컬 Claude Code 이어서 작업용 프롬프트

사용법: 로컬에서 저장소를 클론하고 브랜치를 체크아웃한 뒤 `claude`를 실행하고, 아래 `---` 사이 내용을 통째로 붙여넣으세요.

```
git clone https://github.com/choivoo/mk-minewatch-overwatch-.git
cd mk-minewatch-overwatch-
git checkout claude/tracer-overwatch-minecraft-mod-93j6yx
claude
```

---

앞으로 모든 대화와 설명, 커밋 메시지 설명은 평생 한국어로 해줘.

## 프로젝트 목표
"MineWatch": 모드 하나만 설치하면 마인크래프트에서 오버워치를 거의 그대로 플레이할 수 있는 수준의 모드를 만든다.
오버워치의 시스템·UI·연출·영웅 능력을 최대한 똑같이 재현하되, 비주얼은 마인크래프트의 큐브(블록) 스타일을 유지한다.
(복잡한 3D 모델 대신 Blockbench 스타일의 큐브 기반 모델 사용.)

## 현재 상태 (이미 구현됨, 브랜치 claude/tracer-overwatch-minecraft-mod-93j6yx)
- Fabric 1.21.1 / Java 21 / Yarn 매핑 / Fabric API 0.116.17+1.21.1, `./gradlew build` 성공 확인. 단, 실제 게임 실행 테스트는 아직 한 번도 안 했다. 먼저 `./gradlew runClient`로 실행해서 동작을 확인하고 버그부터 고쳐줘.
- 소스 세트 분리: `src/main`(공통/서버), `src/client`(클라이언트 전용).
- 프레임워크: `hero/Hero`(추상), `HeroState`, `HeroRegistry`, `server/HeroManager`(플레이어별 영웅/상태, 매 틱 처리 + `StatePayload` 동기화), `server/OwDamage`(OW 피해 단위 → 마크 피해, 무적시간 제거, 넉백 복원), 네트워크 `InputPayload`(C2S, 매 틱 버튼 비트 + 이동 입력), `StatePayload`(S2C, HUD 상태).
- HP 규칙: 오버워치 체력 150 = 마크 체력 20 (`Hero.HP_SCALE = 7.5`).
- 트레이서(`hero/Tracer`, `TracerState`): 펄스 쌍권총(히트스캔 40발/초, 탄창 40, 재장전 1초, 헤드샷 2배, 15~30m 감쇠 100→50%), 블링크(7블록, 입력 방향, 0.25블록 단계 충돌검사, 충전 3개/3초), 리콜(20Hz 60틱 기록 역재생, 무적, 최고 체력 복구, 쿨 12초), 펄스 폭탄(`server/PulseBombs`, 포물선·부착·폭발, 서버 시뮬레이션), 근접(V).
- 클라이언트: `MineWatchClient`(키 입력 수집/전송, 영웅 활성 시 웅크리기·드롭 키 소비, 권총 든 동안 바닐라 공격/채굴 차단, 사격 반동), `OverwatchHud`(체력, 탄약, 블링크 충전, 리콜 쿨다운, 궁극기 게이지, 리콜 파란 섬광).
- 명령어: `/minewatch hero <id|none>`.
- 아이템 `pulse_pistols`는 임시 16x16 텍스처(`handheld` 모델).

## 앞으로 구현할 것 (우선순위 순서, 하나씩 끝낼 때마다 빌드·실행 확인 후 커밋)

### 0단계: 안정화
1. `./gradlew runClient`로 실행해 현재 기능을 실제로 검증하고 버그 수정. 특히 확인할 것: 블링크 후 서버/클라 위치 불일치, 리콜 중 순간이동 패킷 끊김, 사격 시 `timeUntilRegen` 처리, Q/Shift 키 충돌 처리, 멀티플레이(전용 서버 + 클라 2개)에서의 동작, 지연 상황에서도 능력이 깨지지 않는지(틱 기반 설계 점검).
2. 단위 테스트 가능한 순수 로직(감쇠 계산, 쿨다운, 기록 버퍼 등)은 JUnit 테스트 추가. 가능하면 Fabric gametest도 구성.
3. 코드 구조 정리: 영웅별 능력을 `Ability` 인터페이스(쿨다운/충전/입력 슬롯)로 일반화해서 새 영웅이 쉽게 추가되게 리팩터링.

### 1단계: 오버워치 공통 시스템 (모든 영웅 공용)
1. **HUD 완성도**: 바닐라 체력/배고픔/경험치/핫바 HUD를 숨기고(Mixin 또는 Fabric 렌더 이벤트) 오버워치 HUD로 완전히 대체. 체력 + 방어구(노란색) + 보호막(파란색) 3종 체력 바, 킬피드, 피해 방향 표시, 힛마커/킬 마커, 궁극기 원형 게이지(%), 능력 아이콘(쿨다운 원형 스윕), 크로스헤어(영웅별), 상단 점수/타이머 바.
2. **체력 시스템 일반화**: 영웅별 최대 체력/방어구/보호막, 힐 수치, 자연 회복 없음(보호막만 일정 시간 후 재생), 힐팩 엔티티(대/소, 리스폰 타이머)와 퍽 연동 훅.
3. **궁극기 시스템**: 영웅별 비용, 피해/치유/자연 충전 비율, 궁극기 준비 알림 사운드·음성.
4. **사운드**: 영웅별 사운드 이벤트 등록(`sounds.json`), 발사·재장전·블링크·리콜·폭탄 비프음·궁극기 음성 라인. 저작권이 있는 원본 오디오는 쓰지 말고 직접 만든/합성한 대체음 또는 사용자가 넣을 수 있는 리소스팩 구조로 만들어줘.
5. **퍽 시스템(오버워치 2)**: 피해·킬로 경험치 획득, 일정 구간마다 마이너 퍽 2택1, 메이저 퍽 2택1 선택 UI, 영웅별 퍽 데이터 정의(트레이서 포함: 힐팩 습득 시 블링크 충전 등).
6. **영웅 선택 UI**: 전용 화면(역할별 탱커/딜러/서포터 탭, 영웅 초상화 자리, 능력 설명), 단축키로 열기, 스폰 중/라운드 대기 중에만 변경 가능하게.

### 2단계: 비주얼/애니메이션 (큐브 스타일 유지)
1. **GeckoLib(또는 동등한 애니메이션 라이브러리)** 도입 검토 후 적용. 1인칭 팔/무기 모델과 3인칭 플레이어 모델 모두 영웅별로 교체 가능하게.
2. 트레이서 펄스 쌍권총을 Blockbench 큐브 모델로 제작(양손, 총구 라이트 발광), 발사 시 번갈아 발사 애니메이션, 장전 모션.
3. 3인칭 애니메이션: 사격, 궁극기 투척, 리콜(총을 놓았다가 도착 직전 다시 잡기), 블링크 잔상.
4. 이펙트: 총구 섬광, 탄도(트레이서 빔), 리콜 시간 소용돌이가 별로 줄어들며 사라지는 연출, 블링크 화면 왜곡, 펄스 폭탄 부착 시 발광 + 폭발 이펙트. 지금 서버 파티클로 임시 처리한 것을 커스텀 파티클/렌더러로 교체. 필요하면 폭탄을 서버 시뮬레이션에서 **커스텀 엔티티**로 전환(클라이언트 렌더링 포함).
5. 임시 아이템 텍스처를 제대로 된 큐브 스타일 텍스처로 교체. 에셋을 만들 수 없는 부분은 자리표시자 + `docs/ASSETS_TODO.md`에 필요한 에셋 목록으로 남겨줘.

### 3단계: 게임 모드/맵/팀 (이게 있어야 "오버워치를 마크에서 플레이"가 된다)
1. 팀 시스템(2팀, 팀 색상, 아군 피해 없음, 팀 채팅), 스폰 룸, 리스폰 타이머, 관전.
2. 게임 모드: 점령(Control), 호위(Escort/Payload), 혼합(Hybrid), 쟁탈전, 플래시포인트 중 우선 점령과 호위부터. 라운드/타이머/점수/연장전/승패 연출.
3. 맵 시스템: 맵 정의 파일(JSON: 스폰, 거점, 페이로드 경로, 힐팩 위치), 관리자용 맵 설정 명령어, 샘플 소형 맵 1개(월드 템플릿 또는 구조물).
4. 로비/매치메이킹: `/minewatch queue`, 매치 시작/종료, 결과 화면(POTG 비슷한 하이라이트는 후순위).
5. 서버 설정 파일(Fabric config)로 수치 조정 가능하게(데미지 배율, 리스폰 시간 등).

### 4단계: 영웅 추가
공통 프레임워크가 안정되면 영웅을 역할별로 추가한다. 영웅 하나당 한 번에 끝내고 커밋.
- 딜러: 솔저: 76, 겐지, 리퍼, 위도우메이커, 에코 순
- 탱커: 라인하르트, 디바, 로드호그, 윈스턴 순
- 서포터: 메르시, 아나, 루시우, 모이라 순
각 영웅은 오버워치 실제 수치(체력, 피해, 쿨다운, 이동속도)를 기준으로 하되 마크 스케일에 맞게 조정하고, 수치는 한 곳(데이터 클래스/JSON)에 모아 밸런스 조정이 쉽게 해줘. 이동속도/점프/중력 같은 영웅별 이동 차이는 attribute modifier로 구현.

### 5단계: 마무리
- 키 바인딩 설정 화면 정리, 한국어/영어 번역 완성, 리소스팩 호환, 성능 프로파일링(초당 40발 히트스캔 + 파티클 부하), README와 사용자 문서 정리, GitHub Actions 빌드 워크플로, 릴리스용 jar 배포 준비(Modrinth/Discord용).

## 작업 규칙
- 한 단계(또는 한 기능)씩 진행하고, 끝날 때마다 `./gradlew build`와 가능하면 `./gradlew runClient`로 확인한 뒤 의미 있는 단위로 커밋해줘. 푸시는 내가 말하기 전엔 하지 마.
- 서버가 권위를 가지는 구조 유지(클라이언트는 입력만 보내고 서버가 판정). 틱 레이트(20TPS) 기준으로 설계하고, 지연이 있어도 능력이 깨지지 않게 해줘.
- 영웅 추가가 쉬운 확장 구조를 우선하고, 하드코딩된 수치는 상수/데이터로 분리해줘.
- 오버워치 공식 에셋(모델, 텍스처, 음성, 음악)은 그대로 복사하지 말고, 직접 만든 큐브 스타일 에셋이나 자리표시자를 사용해줘. 에셋이 필요한 부분은 목록으로 정리해서 내가 만들 수 있게 해줘.
- 모르거나 선택이 필요한 부분(예: GeckoLib 도입 여부, 게임 모드 우선순위, 마크 버전 고정 등)은 짧게 물어보고, 나머지는 합리적인 기본값으로 진행해줘.
- 매 단계 시작 전에 짧은 계획(무엇을 만들지, 어떤 파일을 건드릴지)을 보여주고, 끝난 뒤에는 구현한 것과 아직 안 된 것, 테스트한 방법을 솔직하게 정리해줘.

먼저 0단계(실행해서 현재 구현 검증)부터 시작해줘.
